제안요청서(RFP) 과업 분석 및 벤치마킹 명세

과업지시서에 명시된 사업명 '공공데이터 기반 다차원 상권·입지 분석 및 인사이트 리포트 플랫폼 구축(Biz-Compass)'을 바탕으로 현행 공공데이터 조회의 구조적 한계를 분석하고, 지리공간(GIS)과 통계 데이터를 융합한 To-Be 목표를 수립했습니다.

분석 항목 기존 공공데이터포털 / 시중 상권분석 (As-Is) Biz-Compass 플랫폼 구축 방향 (To-Be)
데이터 표현 방식 단순 그리드 테이블 형태의 텍스트 데이터 조회, 시각적 직관성 결여 GIS 좌표 기반의 실시간 공간 버퍼링, 반경 원 및 행정동 폴리곤 시각화[cite: 1]
분석 알고리즘 깊이[cite: 1] 단일 지표 단순 나열 (점포 수, 유동인구 숫자만 개별 표출) 유동인구 흐름(+) + 경쟁 점포 밀집도(-) + 배후 세대수를 결합한 복합 스코어링 엔진[cite: 1]
후보지 의사결정 지원[cite: 1] 후보지를 각각 따로 검색하여 사용자가 수작업으로 지표를 기억하고 대조해야 함 A/B 후보 상권 1:1 맞대응 실시간 교차 대조 모드 및 정량적 상권 우위 판정[cite: 1]
비용 및 리스크 관리 임대료와 매출을 연계하지 못해 과밀 경쟁 골목 진입 후 폐업하는 사례 빈번 국토부 실거래가 기반 임대료 시세 추정과 5개년 시계열 차트 및 폐업률 경보 제공[cite: 1]
결과 산출물 도출[cite: 1] 단순 화면 캡처 수준에 그쳐 실제 사업계획서 제출용 증빙 불가 원클릭 인쇄용 종합 리포트 자동 생성 뷰어 및 원천 데이터 UTF-8 CSV 익스포트[cite: 1]

공공데이터포털 오픈 API 연계 규격 및 캐싱 검토서

과업지시서 2장 가목(데이터 파이프라인)에 따른 공공 상권정보 및 실거래가 인터페이스 규격 분석[cite: 1]

1. 소상공인시장진흥공단 상가(상권)정보 API[cite: 1]

REST / JSON[cite: 1]

• 기본 엔드포인트: https://apis.data.go.kr/.../storeListInRadius

• 요청 파라미터(Request):

  • radius : 검색 반경 거리 (300, 500, 1000m)[cite: 1]
  • cx, cy : 중심 기준점 경도/위도 좌표 (WGS84)
  • indsLclsCd : 상권 표준 업종 대분류 코드 (외식, 소매, 서비스 등)[cite: 1]

• 응답 필드(Response): bizesId(업소ID), bizesNm(상호명), lon/lat(좌표)

엔지니어링 검토 결론:

사용자가 지도를 이동하거나 반경을 바꿀 때마다 공공 API를 직접 호출하면 일일 트래픽 쿼터(1,000회 제한) 초과 및 지연이 발생하므로, 백엔드 PostGIS 공간 DB에 사전 적재하고 IndexedDB 기반 클라이언트 캐싱 계층을 구축해야 함[cite: 1].

2. 국토교통부 상업·업무용 부동산 실거래가 API

REST / XML

• 기본 엔드포인트: https://apis.data.go.kr/.../getNRGTradeList

• 요청 파라미터(Request):

  • LAWD_CD : 5자리 법정동 시군구 코드 (예: 강남구 11680)
  • DEAL_YMD : 거래 실거래 계약년월 (YYYYMM)
  • serviceKey : 공공데이터포털 발급 보안 인증키[cite: 1]

• 응답 필드(Response): dealAmount(매매가), monthlyRent(월세), rentDeposit(보증금)

엔지니어링 검토 결론:

상가 점포 단위와 부동산 필지 단위를 연결하기 위해 '동코드 + 지번' 기준 복합 외래키를 설계하고, 최근 5개년 분기별 매매·임대 시계열 라인 차트를 출력할 수 있도록 정규화 테이블을 구성해야 함[cite: 1].

Layer 3. 데이터베이스 및 수집 파이프라인 (Persistence Layer)
PostgreSQL + PostGIS & Batch Worker[cite: 1]
PostgreSQL + PostGIS 공간 데이터베이스 Primary Database

250만 전국 상가업소 및 실거래 필지를 Point(위도, 경도, 4326) 및 Polygon 타입으로 적재. **GIST 공간 인덱스**를 통해 반경 검색 속도를 획기적으로 개선[cite: 1].

새벽 비동기 배치 수집기 (Batch Sync Worker) Cron Scheduler[cite: 1]

매일 새벽 3시, 외부 공공 API를 순회 호출하여 신규 인허가 점포 및 실거래 신고 데이터를 자동으로 동기화하고 정제 적재하는 무중단 파이프라인[cite: 1].

■ DFD Level 1: 사용자 요청에 따른 데이터 흐름 5단계 시나리오

  1. [클라이언트 ➔ API]: 사용자가 지도에서 반경(예: 500m)을 클릭하면 중심 좌표(lat, lng)와 업종 코드를 파라미터로 담아 GET 요청 전송[cite: 1].
  2. [캐시 검증]: 백엔드 Cache Layer가 해당 좌표 버퍼가 최근 12시간 내 조회된 이력이 있는지 확인 (Hit 시 즉시 반환)[cite: 1].
  3. [공간 인덱스 쿼리]: Cache Miss 시 PostGIS DB에서 ST_DWithin(geom, ST_MakePoint(lng, lat)::geography, 500)를 수행하여 50ms 이내 점포 목록 추출[cite: 1].
  4. [스코어링 및 집계]: Spatial Engine이 추출된 점포 수와 매핑된 유동인구 데이터를 융합하여 5대 역량 점수(0~100점)를 동적 연산[cite: 1].
  5. [대시보드 렌더링]: 프론트엔드가 수신한 JSON 데이터를 기반으로 지도 마커 클러스터링과 우측 차트를 동시에 양방향 동기화 리렌더링[cite: 1].
